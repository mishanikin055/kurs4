# Сравнительный анализ аннотаторов

## Назначение и состояние

Третье обязательное сравнение: четыре отдельные image-captioning/VLM-модели создают **общее описание исходного изображения**. Список меток детектора не заменяет аннотацию. На 09.10.2026 реализован независимый экспериментальный модуль `annotation/`, веса загружены и проверены; четыре checkpoint прошли реальные офлайн GPU-smoke. Автоматическое сравнение test500 завершено: все четыре модели по 500 изображений без ошибок, один проход. Человеческие оценки и внешний набор остаются незавершёнными. Приложение и конвейер не реализованы.

Предварительные кандидаты из плана: **BLIP base** (`Salesforce/blip-image-captioning-base`), **Florence-2 base-ft** (`microsoft/Florence-2-base-ft`), **Qwen3-VL 2B Instruct** (`Qwen/Qwen3-VL-2B-Instruct`), **SmolVLM2 500M Video Instruct** (`HuggingFaceTB/SmolVLM2-500M-Video-Instruct`). Это не доказанный топ-4. Официальные revisions, лицензии и критерий фиксации — [docs/annotation_model_selection.md](docs/annotation_model_selection.md) и `annotation/configs/models.json`. Суффикс ft означает готовое дообучение авторами, собственного обучения нет. Video в названии SmolVLM2 не требует поддержки видео.

## С чего начать

Прочитать [experiments.md](experiments.md) и ресурсные правила [infrastructure.md](infrastructure.md). Проверить существующий код и контейнеры, не предполагать наличие annotation/CLI из плановой структуры. Зафиксировать каталог весов отдельно до загрузки; общий исходный ориентир — `models/`. Создать реальные адаптеры, manifests и команды, начиная с небольшого smoke, затем фиксировать протокол до test.

Qwen3-VL 2B проверить рано на 6 ГБ VRAM и фактическом лимите RAM WSL. Если требуется offload или квантование, оформить отдельный режим с измеренными RAM/VRAM и качеством. Не заменять кандидата молча после OOM/test. SmolVLM2 выбран в варианте 500M. trust_remote_code по умолчанию не включать; при необходимости проверить код и закрепить commit.

## Данные и генерация

- Зафиксированы COCO val2017 с официальными captions: dev100 из project-local detector dev500 и test500 из detector test4500, seed 42. Manifests — `annotation/configs/{dev100,test500}.json`; одинаковые 500 test-изображений для всех четырёх, dev/test не пересекаются. Это локальные разбиения val2017, не официальный скрытый test COCO.
- Для внешней оценки предусмотреть 100–200 собственных/разрешённых изображений с происхождением и эталонными описаниями. Проверить известные пересечения COCO с обучающими наборами checkpoint; неизвестное пересечение указать как ограничение.
- Основное сравнение на английском: кратко описать видимые объекты, действия и обстановку без догадок. Русский вывод/перевод — отдельная оценка.
- Передавать исходное изображение без overlay и ответов детектора/классификатора. Сохранить точные model-specific prompts/task tokens с одинаковой семантической задачей.
- До test закрепить decoding, stop rules и бюджет токенов; Фактический конфиг — greedy, максимум 96 новых токенов, `annotation/configs/benchmark.json`. Сохранять текст неизменным как raw_caption, число токенов, параметры и ошибки.

## Метрики и результат

Основные: CIDEr и экспертная фактическая корректность. Дополнительные: BLEU-4, ROUGE-L, CHAIR, полнота/информативность/длина; SPICE только при доступном проверенном evaluator. CHAIR считать по GT и проверенной методике/словарю; расхождение с детектором — отдельная метрика.

Слепая перемешанная экспертная выборка — 100 одинаковых изображений для четырёх моделей; желательно два оценщика, при одном указать ограничение. Оценить корректность, полноту, связность, полезность для поиска по шкале 1–5; отметить выдуманные объекты, действия и свойства. LLM-судья не подменяет экспертов.

Измерять всю генерацию, отдельно preprocess/generate/postprocess, выходные токены и tokens/s, p50/p95, холодную загрузку, RAM/VRAM, failed/OOM. Одинаковый предел токенов не гарантирует одинаковую длину. FP32/FP16/offload/quantization явно разделять; batch 1 и одна модель в памяти обязательны.

По актуальному указанию пользователя от 09.10.2026 **один полный прогон каждой
из четырёх моделей**, `repeats=1`. Не запускать три повтора из прежнего плана.
Качество, p50/p95, tokens/s и ресурсы брать из этого единственного прохода;
устойчивость времени или совпадение генерации между повторами по нему не заявлять.
Smoke и dev-проверки до фиксации test-протокола — отдельные проверки, не дополнительные
полные test-прогоны. Одинаковое число прогревов закрепить до test с учётом ресурсов.
**Новые доверительные интервалы не рассчитывать**, в том числе bootstrap; старые
примеры и общие настройки не отменяют это указание.

Выход сравнения: воспроизводимые CSV/Markdown, сырые captions/timings/errors, конфиги, manifests и реально использованные Python-скрипты/команды. Числа публиковать только после локальных прогонов. Согласование и повторная генерация относятся к [pipeline.md](pipeline.md), не меняют базовое независимое сравнение.

## Проверки

Проверить JSON-контракт, сохранение raw_caption, отсутствие входных ответов детектора в базовом caption, офлайн smoke каждого checkpoint, последовательное освобождение процессов, OOM и неполный отчёт. Mock-тесты и реальные model smoke описывать отдельно.

## Реализация от 09.10.2026

Команды — [annotation/README.md](annotation/README.md). Веса отдельно в
**annotation/models/**, SHA-256 — `annotation/models/manifest.json`.
Заранее зафиксированы dev100 из detector dev500 и test500 из detector test4500:
`annotation/configs/dev100.json`, `annotation/configs/test500.json`.
COCO captions — официальные val2017, split project-local, не официальный test COCO.

FP16 без offload/quantization, batch1, один прогрев на dev, максимум 96 completion
токенов, greedy, repeats1. Qwen ограничен 65536–262144 pixels; BLIP/Florence
eager, Qwen/Smol SDPA. Florence использует проверенный закреплённый авторский
код local-only и legacy-cache; остальные trust_remote_code=False.
Нативный Florence smoke и первые проверки совместимости failed сохранены;
успешный smoke не заменяет основной test.

[Метрики и проверенная CHAIR-методика](annotation/evaluation/README.md):
CIDEr, BLEU-4, ROUGE-L, CHAIRs/CHAIRi, дополнительная объектная полнота,
тайминги и ресурсы. Слепые экспертные формы подготовлены из результатов и остаются локальными;
человеческие оценки пока отсутствуют. Внешний разрешённый набор не предоставлен,
SPICE evaluator не валидирован. BLIP и SmolVLM2 имеют известное использование
COCO в обучающих источниках; полной независимости test500 не заявлять.

500 — практический бюджет первого основного эксперимента внутри предложенного
диапазона 500–1000. Выбор случайный (shuffle seed 42 из test4500), без
стратификации; с crop-набором совпадают 68 сцен. Test500 содержит 2500 references,
3623 instances включая crowd и 79/80 категорий, без toaster; hair drier 1 сцена,
toothbrush 2, scissors 3, bear 4. Формальная достаточность 500 и устойчивость
ранжирования не доказаны; редкие классы отдельно надёжно не оцениваются.
