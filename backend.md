# Backend: API, хранение и очередь заданий

## Назначение и состояние

Backend принимает изображения, создаёт задания, хранит этапы/артефакты и выдаёт статус и результаты интерфейсу. Стек: **FastAPI, PostgreSQL JSONB, SQLAlchemy и миграции, единственный Python worker**. На 09.10.2026 backend приложения ещё не реализован; существующие detection/ и classification/ — CLI-модули сравнения, не готовый web backend.

Для задачи «делай backend» начать с фактического дерева/конфигов и маленького сценария загрузка → очередь → обработка → сохранение → чтение результата. Не создавать endpoints, выдающие фиктивный успех. Для модельного этапа обратиться к [pipeline.md](pipeline.md); для контейнеров — к [infrastructure.md](infrastructure.md). Длинный план для начала не требуется.

## Границы и API

- Разделить HTTP, доменные схемы/статусы, ORM/миграции, файловое хранилище, worker и pipeline. Специфические типы библиотек моделей не входят в публичный JSON-контракт.
- HTTP и UI не держат веса и не выполняют тяжёлый инференс. FastAPI BackgroundTasks не заменяет надёжную очередь долгих GPU-заданий. Для MVP очередь в PostgreSQL и один worker; Redis/Celery только при конкретной необходимости.
- Проверять фактический формат/MIME, размеры и число пикселей изображения; безопасно формировать пути. Не исполнять имена/тексты как команды. Сохранить исходные байты и hash; для нормализованной версии хранить связь с исходной и правило координат.
- Создание задания возвращает job_id сразу; повтор HTTP-запроса с idempotency key не создаёт новое задание. Выдавать текущий этап, частичные результаты, конечные ошибки и файлы по контролируемым маршрутам.
- Pydantic-схемы и ответы имеют schema_version, image_id, job_id, model_version_id; объекты связаны через object_id. Форматы bbox/mapping/caption определены в [pipeline.md](pipeline.md).

## БД и файловые артефакты

Результаты — PostgreSQL JSONB, изображения — отдельные файлы со ссылкой, SHA-256, MIME и размером. Base64 в JSON результата не сохранять. PostgreSQL не подменять SQLite при проверках JSONB/миграций/очереди.

Предусмотреть сущности images, model_versions, jobs, stage_results, artifacts, annotation_revisions и сохранённую выдачу поиска. Это проектируемые сущности, не существующие таблицы. stage_results сохраняет статус, payload, timings и версию модели каждого этапа. Исходное изображение, normalized image и overlay сохраняются отдельно. Raw caption неизменен; согласованный текст и ручные правки — отдельные ревизии с происхождением.

## Worker и восстановление

Состояния: queued → running → succeeded | partial | failed | cancelled. Получение задания — короткая атомарная транзакция, при необходимости FOR UPDATE SKIP LOCKED; длительный инференс не удерживает транзакционную блокировку. Хранить worker_id, lease_until, heartbeat, attempts, timestamps и error. Повтор после сбоя не дублирует сохранённые этапы.

Worker-координатор последовательно создаёт дочерний процесс на модельный этап и ждёт его полного завершения; сам веса не загружает. Классификатор один раз обрабатывает все crops этапа. Ошибка caption не удаляет сохранённые детекции/overlay; частичный успех явный. Отмена, timeout, crash и lease expiry останавливают всю модельную группу до освобождения общего `storage/locks/inference.lock`. Истёкшая lease сама по себе не доказывает, что GPU свободна.

API/worker подключаются к db:5432; ui — к api:8000. API получает только нужный storage, без GPU и весов; worker без Docker socket. Сетевой поиск изолируется провайдером — [search.md](search.md).

## Проверки и готовность

Unit: входные изображения/пути, схемы, idempotency, статусы и ошибки. Integration на настоящем PostgreSQL: миграции, JSONB, конкурентное получение задания, сохранение этапов и файлов, повтор/отмена, истечение lease и восстановление после сбоя. Модельные mock-адаптеры допустимы для тестов очереди, реальный smoke указывается отдельно.

Готовность вертикального сценария подтверждается запуском через Compose и получением сохранённого результата через API после перезапуска сервисов. Перед финальной приёмкой — PostgreSQL integration и smoke всех 12 моделей. Обновить README/схемы/миграции и указать фактически выполненные проверки.
