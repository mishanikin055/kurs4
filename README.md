# Image Analysis 0.3.4

Приложение для детекции объектов и описания фотографий. RF-DETR Small находит COCO-объекты, Florence-2-base-ft описывает сцену и каждую вырезку; локальный Marian EN→RU переводит описания на русский. Elasticsearch хранит результаты, S3 — вырезки объектов и общее изображение с рамками bbox. Исходные фотографии постоянно не сохраняются. Результат можно скачать в папку или ZIP.

[Эксплуатация и настройки S3](OPERATIONS.md) · [Изменения версий](CHANGELOG.md) · [Исторические материалы в репозитории](https://github.com/mishanikin055/kurs4/tree/dev/archive/coursework)

## Архив для передачи

Чистый архив приложения содержит код, Docker-конфигурацию, эту инструкцию и `.env` с шаблоном настроек. В нём нет личных секретов, весов, данных, старого SQL-хранилища и сравнительных экспериментов. Веса скачиваются командой ниже; первой установке нужен интернет.

Корневой `.env` в таком архиве — справочный шаблон, **launcher читает `.secrets/app.env`**. Для локального MinIO не копируйте шаблон: launcher сам создаст случайные пароли. Для внешнего S3 создайте `.secrets/app.env` с пятью настройками из шага 4. При повторной установке сохраните существующий файл с паролями; не заменяйте его шаблоном.

## Установка и запуск

1. Установите **Python 3.10+ и Docker с Compose**, запустите Docker. Нужен Linux x86_64 Docker engine: Linux либо Linux-контейнеры Docker Desktop на Windows/Intel Mac. ARM/Apple Silicon и Apple GPU launcher не поддерживает. Персональная WSL и пути автора не нужны.
2. Скачайте ZIP репозитория, распакуйте его и откройте терминал в папке проекта. Проверьте инструменты:

```bash
python3 --version
docker compose version
docker info
```

На Windows во всех командах замените `python3` на `py -3`. Для внешнего S3 нужен современный Compose с поддержкой `!reset`.

3. Скачайте модели детекции, аннотирования и локального перевода:

```bash
python3 scripts/fetch_app_models.py
```

Скрипт использует стандартную библиотеку Python, скачивает закреплённые веса и файлы моделей и проверяет SHA256. Датасеты и сравнительные модели не нужны. При ошибке проверки существующий файл сохраняется; автоматической замены нет.

4. Выберите хранилище вырезок **до первого запуска**:

- **Локальный MinIO:** ничего настраивать не нужно. Launcher создаст `.secrets/app.env` со случайными паролями, поднимет MinIO в Docker и сохранит данные в volume.
- **Свой S3:** создайте закрытый bucket у провайдера. В редакторе создайте папку `.secrets` и файл `app.env` с настройками ниже. Если файл уже существует, измените только эти пять строк, сохранив остальные настройки и пароли:

```dotenv
APP_S3_ENDPOINT_URL=https://s3.example.com
APP_S3_ACCESS_KEY=YOUR_ACCESS_KEY
APP_S3_SECRET_KEY=YOUR_SECRET_KEY
APP_S3_BUCKET=my-image-crops
APP_S3_REGION=us-east-1
```

Адрес — endpoint **S3 API**, без имени bucket и ключей в URL. Замените все примеры значениями провайдера. `localhost` внутри контейнера означает сам контейнер; адрес должен быть доступен из Docker. Подробности про DNS, TLS, права и смену хранилища — в [инструкции S3](OPERATIONS.md#подключение-s3). Не копируйте шаблон поверх существующего `.secrets/app.env` и не публикуйте этот файл. Недостающие локальные настройки launcher добавит сам.

5. Выберите устройство, проверьте окружение и запустите приложение:

```bash
python3 scripts/start_app.py --device cpu --check
python3 scripts/start_app.py --device cpu
```

`--check` проверяет Docker, настройки и веса; не создаёт файлы, не запускает контейнеры и **не проверяет соединение с S3**. Обычный запуск собирает образы, поднимает хранилища/брокер, создаёт индекс и при необходимости bucket, затем запускает API, worker и frontend. Внешний endpoint автоматически отключает локальный MinIO; при ошибке внешнего S3 запуск прекращается без локального fallback.

Для NVIDIA с настроенным Container Toolkit и совместимым драйвером замените `cpu` на `cuda`. Для Docker Engine прямо внутри WSL без NVIDIA runtime используйте `wsl-cuda`: нужны `/dev/dxg` и библиотеки драйвера WSL. CPU автоматически не подставляется. CPU использует FP32, CUDA — FP16 для Florence. **Настоящий CPU-инференс пока не проверен; обработка может быть долгой.**

Первой сборке нужен интернет и значительное место под ML-образ: ориентируйтесь минимум на 30 ГБ свободного диска сверх данных приложения. Launcher задаёт worker лимит RAM 8 ГБ для CPU или 5 ГБ для CUDA; Elasticsearch, MinIO, RabbitMQ и API требуют дополнительную память. Практический ориентир — 16 ГБ RAM и достаточный лимит памяти Docker/WSL. Это ориентиры, а не проверенная матрица аппаратной совместимости.

6. Откройте [приложение](http://localhost:8080). Проверьте доступность хранилищ и брокера:

```bash
curl --fail http://localhost:8080/api/health
```

В Windows PowerShell используйте `curl.exe`. Ожидается `{"rabbitmq":true,"elasticsearch":true,"s3":true}` и HTTP 200. Эта проверка не подтверждает готовность моделей или права записи вырезок: модели загружаются отдельно в worker. [Диагностика](OPERATIONS.md#остановка-и-диагностика) описывает просмотр их логов. При переходе с 0.2.0 сначала прочитайте [порядок обновления](OPERATIONS.md#переход-с-postgresql).

## Работа без интернета

После первой установки Docker-образы и все веса уже находятся на компьютере. Обработка, перевод на русский, документация API и сохранение в локальный MinIO работают без интернета. При обработке фотографии не отправляются во внешние сервисы. Для внешнего S3 нужен доступ к его серверу.

После штатной остановки запустить уже созданные контейнеры без скачивания и сборки можно так (сохраняется ранее выбранное устройство):

```bash
docker compose -p kurs4-app -f compose.app.yaml --profile processing start
```

Docker должен быть запущен. Команда `start` требует контейнеров, созданных ранее launcher; после `down` сначала потребуется создать их заново. Для переноса на другой компьютер нужны также Docker-образы, веса и конфигурация — одного архива кода недостаточно для установки без сети.

## Использование

Выберите JPEG/PNG и нажмите «Отправить». Результат появится автоматически. Нажатие рамки или строки таблицы выделяет объект; остальные рамки остаются видимыми. Русское описание сцены находится под изображением; описания объектов в таблице также переведены на русский. COCO-классы детектора сохраняются в исходном виде. В JSON поля `raw_caption`/`object_caption` содержат исходные ответы Florence, а `russian_caption` — перевод. Старые готовые результаты не пересчитываются; при отсутствии перевода интерфейс показывает исходное описание.

Выбор папки в поддерживаемом браузере включает автоматическую запись результата в неё. Без выбранной папки или при ошибке доступен ZIP: `results.json`, `detection.png` с обведёнными bbox и `crops/<object_id>.png`. Исходные байты не сохраняются; нормализованный PNG временно хранится для очереди и удаляется после успешной публикации. При ошибке он остаётся для повтора обработки. В S3 постоянно хранятся вырезки и изображение с рамками; JSON формируется из Elasticsearch.

Изображение с рамками показывается из выбранного локального файла в текущей вкладке. Сервер сохраняет отдельный `detection.png` со всеми рамками и COCO-подписями: он доступен через `GET /images/{id}/files/detection.png` и входит в выгрузку. Для результатов, созданных до 0.3.3, такой PNG отсутствует; готовые задания автоматически не пересчитываются. Исходник и нормализованное изображение без рамок после обработки недоступны.

API: [Swagger](http://localhost:8080/api/docs). Лимиты: загрузка 10 МиБ и 25 мегапикселей, один артефакт 128 МиБ, комплект 256 МиБ. Поиск, определение цвета и авторизация пока не реализованы. «Классификация» содержит описания объектов Florence и COCO-классы детектора; ViT не запускается.

## Остановка

Дождитесь результата текущего изображения, затем выполните:

```bash
docker compose -p kurs4-app -f compose.app.yaml --profile processing stop
```

Повторный запуск — той же командой `start_app.py --device ...`; launcher также пересобирает приложение после обновления кода. Не удаляйте volumes и не используйте `down -v`: там находятся результаты, вырезки, очередь и незавершённые входы. Смена S3 не переносит сохранённые PNG — сначала прочитайте [порядок переключения](OPERATIONS.md#смена-хранилища).

Веса в Git/ZIP не входят. Секреты хранятся только в `.secrets/app.env`; лицензии весов — рядом с моделями.
