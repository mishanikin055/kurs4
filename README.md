# Image Analysis 0.3.2

Приложение для детекции объектов и описания фотографий. RF-DETR Small находит COCO-объекты, Florence-2-base-ft описывает сцену и каждую вырезку. Elasticsearch хранит аннотацию сцены, классификацию и результаты детекции; вырезки хранятся в локальном MinIO или подключённом пользователем внешнем S3. Исходники постоянно не сохраняются. В браузере можно посмотреть результат и по своему выбору сохранить его в папку или ZIP.

## Быстрый запуск из ZIP

1. Скачайте ZIP репозитория и распакуйте его. Откройте терминал в распакованной папке.
2. Установите Python 3.10+ и Docker с Compose. Нужен **Linux x86_64 Docker engine**: Linux либо Linux-контейнеры Docker Desktop на Windows/Intel Mac. ARM/Apple Silicon и Apple GPU этой сборкой не проверены и не поддерживаются launcher. Персональная WSL и пути автора не нужны.
3. Подготовьте только две используемые модели:

```bash
python3 scripts/fetch_app_models.py
```

На Windows вместо `python3` используйте `py -3`. Скрипт использует стандартную библиотеку Python, скачивает около 850 МБ закреплённых весов и проверяет SHA256. Датасеты и остальные сравнительные модели не нужны. При ошибке проверки существующий файл сохраняется; автоматической замены нет.

4. Выберите режим и проверьте окружение:

```bash
python3 scripts/start_app.py --device cpu --check
python3 scripts/start_app.py --device cpu
```

Для NVIDIA с настроенным Container Toolkit и совместимым драйвером замените `cpu` на `cuda`. CUDA не обязательна для CPU-режима. CPU работает с FP32, CUDA — с FP16 для Florence. **Настоящий инференс в CPU-режиме пока не проверен; время обработки может быть большим.**


Для прямого Docker Engine внутри WSL без NVIDIA Container Toolkit используйте явный режим:

```bash
python3 scripts/start_app.py --device wsl-cuda
```

Он требует `/dev/dxg` и библиотек драйвера WSL. Обычный `--device cuda` требует настроенного NVIDIA runtime Docker; launcher проверяет его до сборки.

Launcher определяет папку проекта по своему расположению, создаёт случайные пароли без перезаписи существующих настроек, собирает контейнеры, поднимает Elasticsearch/RabbitMQ и при локальном S3 — MinIO, создаёт индекс и bucket и запускает приложение. `--check` ничего не создаёт и не запускает; проверяет настройки и веса, но не соединение с внешним S3. При переходе с 0.2.0 сначала выполните шаги обновления в [технической документации](OPERATIONS.md).

Первой сборке нужен интернет и значительное место под ML-образ: ориентируйтесь минимум на 30 ГБ свободного диска сверх медиаданных. Для CPU launcher задаёт worker 8 ГБ RAM, для CUDA — 5 ГБ; Elasticsearch (лимит 1 ГБ), MinIO, RabbitMQ и API требуют дополнительную память. Практический ориентир — хост с 16 ГБ RAM и достаточной памятью Docker. В WSL отдельно учитывайте лимит RAM виртуальной машины и память VS Code/других процессов: 16 ГБ на Windows не означают 16 ГБ внутри WSL. Это ориентиры, а не подтверждённая матрица аппаратной совместимости.

## Выбор S3

Если `.secrets/app.env` отсутствует, `APP_S3_ENDPOINT_URL` не задан, пустой или равен `http://s3:9000`, launcher использует локальный MinIO и генерирует локальные секреты. Для своего S3 задайте в `.secrets/app.env`:

```dotenv
APP_S3_ENDPOINT_URL=https://s3.example.com
APP_S3_ACCESS_KEY=YOUR_ACCESS_KEY
APP_S3_SECRET_KEY=YOUR_SECRET_KEY
APP_S3_BUCKET=my-image-crops
APP_S3_REGION=us-east-1
```

Адрес — S3 API, без имени bucket; регион и ключи возьмите у своего провайдера. При таком адресе launcher автоматически исключает MinIO из сборки и запуска, снимает зависимость API/worker от него и останавливает прежний локальный контейнер после успешного переключения. Используйте прежнюю команду `start_app.py --device ...`; вручную выбирать Compose-файлы не нужно. При неполных настройках или недоступном внешнем S3 запуск завершается ошибкой, без переключения на локальное хранилище. Доступность bucket проверяется до запуска нового worker. `MINIO_*` относятся только к локальному серверу.

Рекомендуется заранее создать bucket и выдать ключам права проверки bucket, записи и чтения объектов. Если bucket отсутствует, инициализация пробует создать его — для этого нужны дополнительные права. Соединение использует path addressing и стандартную проверку TLS; временные credentials с session token и специальный CA отдельно не настроены. Реальный облачный провайдер пока не проверен.

Смена endpoint/bucket не переносит прежние вырезки: старые документы Elasticsearch будут искать объекты уже в новом хранилище. Для доступа к ним потребуется скопировать объекты с сохранением ключей либо вернуть прежние настройки. Локальный volume не удаляется. Перед переключением остановите приложение и дождитесь завершения обработки.

## Использование

Откройте [приложение](http://localhost:8080). Выберите JPEG/PNG и нажмите «Отправить». Результат появится автоматически. Нажатие рамки или строки таблицы выделяет объект; остальные рамки остаются видимыми. Описание сцены находится под изображением.

Выбор папки в поддерживаемом браузере включает автоматическую запись результата в эту папку. Без выбранной папки или при ошибке доступен ZIP. Клиентская выгрузка содержит `results.json` и `crops/<object_id>.png`. Исходные байты после проверки не сохраняются. Нормализованный PNG временно хранится в общем каталоге API/worker для очереди и удаляется после успешного сохранения результата. При ошибке он остаётся для повтора обработки. В S3 сохраняются только вырезки; JSON формируется из Elasticsearch.

Изображение с рамками показывается из выбранного локального файла в текущей вкладке браузера. Сервер после обработки не может вернуть исходник, нормализованную фотографию или полное изображение с рамками.

API: [Swagger](http://localhost:8080/api/docs). Загрузка ограничена 10 МиБ и 25 мегапикселями. По умолчанию один артефакт ограничен 128 МиБ, комплект — 256 МиБ. Поиск в интерфейсе, определение цвета и авторизация пока не реализованы. «Классификация» сохраняет описания объектов от Florence и COCO-классы детектора; отдельная ViT-модель не запускается.


## Остановка и диагностика

```bash
docker compose -p kurs4-app -f compose.app.yaml --profile processing logs --tail 100 -f backend worker
docker compose -p kurs4-app -f compose.app.yaml --profile processing down
```

Не добавляйте `-v` при обычной остановке: эта опция удаляет данные volumes. После перезагрузки используйте ту же команду launcher с выбранным устройством. При обновлении кода пересборка выполняется launcher автоматически.

Веса в Git/ZIP не входят. Секреты находятся только в `.secrets/app.env`; пользовательские изображения и локальные тяжёлые отчёты исключены из Git. Сторонние лицензии весов сохраняются рядом с моделями.
