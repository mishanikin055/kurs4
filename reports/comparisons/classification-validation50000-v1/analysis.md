# Сравнительный анализ: ImageNet validation50k

Все четыре готовых checkpoint завершили выбранные для анализа повторы: 2 на модель. Обучение, fine-tuning и LoRA не выполнялись. Качество — первый повтор; время и пиковые ресурсы — первые 2 повтора. Предсказания, включая top5 и softmax, совпали между выбранными повторами. Новые доверительные интервалы не рассчитывались.

Полная официальная ImageNet validation: 50 000 одинаковых изображений, 1000 классов по 50 изображений. Источник ILSVRC/imagenet-1k, revision 49e2ee26f3810fb5a7536bbf732a7b07389a47b5. Настройки на этом наборе не подбирались. В анализ включено 400000 обработок, число разных изображений — 50 000. Предварительная evaluation5000 входит в эти 50 000 и не является независимым набором.

Почему 50 000: использован весь официальный проверочный набор ImageNet, по 50 снимков для каждого из 1000 классов. Размер не подбирался под победителя. Предварительные 5000 (по 5 на класс) служили быстрым первым сравнением, затем пользователь поручил полную проверку. Они входят в полный набор и не образуют второе независимое подтверждение.

По изменённому указанию пользователя от 09.10.2026 сравнение заканчивается после двух кругов. Исходный repeats=3 сохранён в experiment.json; выбор первых двух повторов записан отдельно в report/verification manifests. Уже готовые дополнительные проходы (resnet50_repeat3) сохранены и исключены из основной таблицы.

Наибольшая Top-1 в этом режиме у EfficientNetV2-S: 84.238%. Минимальная p50 у ResNet-50: 10.22 мс. Это описательное ранжирование измеренных значений.

Число правильных первых ответов: ResNet-50 — 40427 из 50000; EfficientNetV2-S — 42119 из 50000; ConvNeXt-Tiny — 41257 из 50000; ViT-B/16 — 40534 из 50000.

Максимальный Macro-F1 у EfficientNetV2-S: 0.83996. Этот критерий одинаково взвешивает присутствующие классы, тогда как Top-1 зависит от числа объектов каждого класса.

Разница между первым и вторым результатом (ConvNeXt-Tiny) составляет 1.724 процентного пункта, или 862 правильных первых ответов. Их отношение медианных задержек — 2.09.

Штатные входы: EfficientNetV2-S 384×384; ResNet-50, ConvNeXt-Tiny и ViT-B/16 224×224 с разными resize. Отличаются обучающие рецепты готовых весов. Разницу нельзя приписывать только архитектуре. Сохранённые повторы ResNet-50 выполнены ранее, остальные — при продолжении; порядок временных измерений не полностью перемешан. Влияние состояния ноутбука на задержки не исключено.

Задержки p50/p95 вычислены по объединённым измерениям первых 2 повторов. Средние стадий и холодной загрузки приведены в таблице выше; ресурсы — максимальные пики среди выбранных повторов. Холодная загрузка не включает очистку page cache. Развёрнутые CSV содержат также чтение, запись/fsync и, для вырезок, кадрирование.

FP32, batch 1, 20 прогревов, 4 CPU threads, RTX 4050 Laptop 6 GiB / i5-12450H, WSL2 Linux Docker, PyTorch 2.7.1 CUDA 12.8 / torchvision 0.22.1. Строго один модельный дочерний процесс с общим inference.lock, runtime без сети и токена. CUDA синхронизируется на границах стадий. p50/p95 включают preprocessing/transfer, forward и postprocessing; чтение, crop, запись/fsync и холодная загрузка вынесены отдельно. RAM — peak RSS; VRAM — пики PyTorch, не полная память GPU.

Таблица и детализация — в этой папке; сырые predictions/timings/errors и source_snapshot — reports/classification/validation50000-v1/. Проверка — reports/verification/classification-validation50000-v1.json. Команды воспроизведения — classification/README.md и classification/crops/README.md; scripts/verify_classification.py проверяет хеши, эталоны, метрики и повторы, scripts/analyze_classification.py строит этот текст без нового инференса.
