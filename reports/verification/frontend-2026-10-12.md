# Проверка простого фронтенда, 12.10.2026

Реализован отдельный nginx frontend в `compose.app.yaml` на локальном порту 8080.
Статические HTML/CSS/JavaScript без npm-зависимостей в приложении. API дополнен
чтением статуса и сохранённого detector PNG; компактный GET результатов сохранён.
Применены подходящие рекомендации design-taste-frontend для прикладного интерфейса,
без маркетинговых блоков и декоративных изображений. Параметры дизайна: 4/2/4.

## Границы проверки

Реальные модели, научные сравнения и новая загрузка в работающий Celery не запускались.
Интеграция новых endpoint с реальным инференсом остаётся отдельным smoke.
Рабочая БД до обновления уже была на `b7d91f4e20ac (head)`; миграции не применялись.
Worker, PostgreSQL, RabbitMQ и volumes не пересоздавались.
Прежние незакоммиченные изменения backend сохранены; эта работа не фиксирует их в Git.

Авторизации нет, HTTP-порты привязаны к loopback. PNG содержит исходные
COCO-категории, классификация и семантическое уточнение показаны отдельно.
Выбор другого файла не отменяет уже созданное задание.

## Исправление работающей установки после обращения пользователя

Пользователь загрузил изображение через UI; все три результата сохранены,
но `image_ready=false`. Причина: ранее работавший worker был собран до добавления
`save_detection_image`, а его image volume оставался read-only. API и frontend
были обновлены отдельно, что не обновило worker автоматически.

Для задания `6d7292b4-3d9e-488f-9150-5097b37a08f1` PNG восстановлен из уже
сохранённого detection payload и normalized.png штатной функцией storage,
без повторного инференса и изменения результатов БД. Проверены `image_ready=true`
и HTTP 200 `image/png` через nginx. Перед обновлением worker очередь БД пуста:
единственное задание succeeded, queued/running отсутствуют.
Worker пересобран и пересоздан с `compose.app.gpu.yaml` и записью в image volume.
README дополнен обновлением старого worker. Новый модельный прогон не выполнялся.
