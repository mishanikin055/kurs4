# Сохранение детекции и соответствия COCO/ImageNet — 12.10.2026

## Реализация

- `storage.py`: атомарный PNG с исходными COCO-рамками/подписями,
  `<image_directory>/jobs/<job_id>/detection.png`. Исходные файлы не изменяются.
- `processing.py`: запись сразу после детекции и до классификатора. При ошибке
  диска детекции остаются в БД, partial/detection_image_error; следующие этапы
  продолжаются. PNG сохраняется и при пустой детекции, переживает ошибки
  классификации/аннотирования и повторную доставку.
- `models.py`, `checkpoints.json`: crop с отступами 10% ширины/высоты с каждой
  стороны, с округлением наружу и ограничением размерами PNG. Bbox в БД прежний.
- `service.py`, `schemas.py`: вычисляемая `semantics` по object_id;
  same/refinement/conflict/unmapped/unavailable. При refinement используется
  ImageNet-подтип, в остальных случаях effective_label остаётся COCO.
  Исходные результаты моделей и raw_caption не заменяются.
- `imagenet_coco_mapping.json`: компактные группы synsets из исторического
  ручного mapping, 287 классов ImageNet / 56 категорий COCO; словарь имён
  используется существующий. Исторические данные не изменяются.
- `compose.app.yaml`: image volume worker теперь writable.
  Активные инструкции и README обновлены, новые миграции для задачи не нужны.

Существовавшие до задачи незакоммиченные изменения компактной БД сохранены.
Рабочие контейнеры, очередь и БД приложения не обновлялись.

## Ограничения и применение

Настоящие модели и GPU smoke не запускались; повышение точности с отступами
не измерено. Словарь частичный и ручной: соответствие категории не доказывает
правильность подтипа. HTTP-выдача PNG и UI не реализованы; путь указан в README.
Старые завершённые задания не получают PNG автоматически.

Для применения завершить очередь перед сменой параметров, пересобрать backend
и worker и пересоздать контейнеры с writable image volume по README.
Если ещё не применена существующая миграция компактной БД, следовать инструкции
резервного копирования/остановки из README; эта задача её не применяла к рабочей БД.
