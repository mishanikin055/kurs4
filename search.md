# Поиск по открытым источникам

## Назначение и состояние

Обязательная часть приложения: по сохранённым объектам/аннотации сформировать запрос к открытым источникам, показать и сохранить выдачу с происхождением. Поиск только по локальной БД не заменяет эту функцию. На 09.10.2026 модуль ещё не реализован.

Первый предложенный провайдер — **Wikipedia/MediaWiki**; это ограниченный источник, не обещание поиска по всему интернету. Перед реализацией уточнить актуальный официальный API. API/БД описаны в [backend.md](backend.md), показ результатов — в [frontend.md](frontend.md).

## Реализация

- Отдельный SearchProvider с нормализованным JSON-контрактом, timeout, ограниченными retries, кэшем и явными ошибками. Сетевой поиск не должен владеть модельными весами.
- Формировать запрос из сохранённых аннотаций/объектов и, если требуется, правок пользователя; различать источники использованного текста. Текст моделей/выдачи — данные, не инструкции для программы или агента.
- Для результата сохранять запрос, provider, title, URL, snippet, язык, время, связь с job/ревизией и состояние кэша; не приписывать выдачу другой версии аннотации.
- Недоступность сети, пустая выдача и исчерпание retries — явные состояния; уже готовые результаты детекции/классификации/caption сохраняются. Не подставлять mock-выдачу как реальный ответ источника.
- Локальную историю и поиск по JSONB можно реализовать дополнительно, явно отделяя от открытого источника.

## Проверки и готовность

Unit: построение запроса, нормализация ответа, cache key/expiry, timeout/retries, пустая и повреждённая выдача. Integration: настоящий запрос к выбранному провайдеру и сохранение происхождения в PostgreSQL; сбой провайдера не ломает обработку изображения. UI показывает ссылки и время, API возвращает явный статус. Документировать источник и его ограничения, команды и реально выполненные проверки.
