# Сравнительный анализ детекторов

Сравниваются готовые COCO-детекторы **YOLO26s, RT-DETRv2 R18, RF-DETR Small,
Faster R-CNN ResNet50 FPN V2 COCO_V1**. Обучения нет; это выбранные архитектурные
представители, а не доказанный мировой рейтинг популярности.

## Активная реализация

Рабочие файлы: `scripts/detection/{yolo26s,rtdetr_v2_r18,rf_detr_small,faster_rcnn}.py`
и `scripts/detection/common.py`. В файле модели находятся локальная загрузка,
штатная подготовка изображения, inference, postprocessing и native predict.
Общий файл читает набор, замеряет стадии, применяет официальный COCO evaluator,
сохраняет результаты и таблицы. Полезные инварианты проверяются в `detection/tests/`.
Не возвращать прежние CLI, adapters, runner и платформу экспериментов.

Команды и объяснение файлов — [detection/README.md](detection/README.md).
Общая подготовка — `scripts/prepare.py`; запуск — `compose.yaml` и при необходимости
`compose.gpu.yaml`. Закреплённые источники, категории и исторические конфиги
сохранены в `detection/configs/`, веса и их manifest — `detection/models/`.

## Протокол новых запусков от 11.10.2026

Один проход COCO test (`data/coco/test.json`, 4500 изображений), batch 1, FP32,
seed 42, 20 прогревов. Все четыре команды получают одинаковый `--run NAME` и,
для короткой проверки, одинаковый положительный `--limit N`.
Новый протокол `detection-simple-v1` записывается в `run.json`; исторический
`detection/configs/benchmark.json` с тремя повторами не переписывается.
Новые результаты — `reports/runs/detection/NAME/`.

Повторная запись результата модели запрещена, resume отсутствует. После
прерывания выбрать новое имя сравнения. Общая identity сравнения проверяет
набор, выбранные изображения, лимит, настройки, исходники и ID контейнера.
Один реальный модельный процесс удерживает общий `storage/locks/inference.lock`
до выхода; родитель по SIGTERM завершает всю группу ребёнка. Только после его
выхода CPU рассчитывает метрики. Одновременно модельные команды не запускать.
Runtime работает офлайн и ничего не скачивает.

Метрики: COCO AP/AR, precision/recall при score 0.5 и IoU 0.5, AP и TP/FP/FN
по всем категориям, p50/p95, throughput, холодная загрузка, peak RAM и PyTorch
allocated/reserved VRAM. Для AP сохраняются score floor 0.001, до 300 исходных
детекций, evaluator maxDets `[1, 10, 100]`. UI-порог не обрезает AP.
Новые CI и bootstrap не рассчитываются. Короткая проверка помечается `shortened`
и не считается итогом полного набора.

Различать sparse COCO IDs и непрерывные индексы. RF-DETR исключает только
неиспользуемые slots 0–90 своей головы; неизвестные ID остаются ошибкой.
`bbox_xyxy` — пиксели исходного изображения, COCO `bbox` — xywh. Проверять
resize, letterbox, границы и EXIF; поворот EXIF отклоняется без преобразования GT.
Native parity, оригинал и overlay автоматически сохраняются для первого изображения.
Дополнительно native parity проверяется на первом неквадратном изображении набора.

## Проверки и сохранённая научная работа

CPU/mock-тесты проверяют evaluator, mapping, координаты, EXIF, статусы,
неполноту, запрет перезаписи, совместимость лимитов, восстановление отчёта
и lock на всём сроке жизни ребёнка. Они не заменяют реальный офлайн smoke.
По последнему указанию пользователя от 11.10.2026 в рамках этой переделки
новые модельные прогоны, пересчёт метрик и заполнение таблиц не выполнять.
Продолжать только CPU/mock-тесты и статические проверки. Будущая реальная
проверка модельных стадий — отдельная задача; полный benchmark автоматически
не повторять.

Исторический **test-v2: 4 × 3 × 4500**, 1000 парных bootstrap-выборок и test-v1
сохранены. Девять проходов перенесены из test-v1, три RF-DETR повторены после
исправления sparse slots; это восстановленное сравнение, а не 12 новых прогонов.
Исходные predictions, timings, CI, конфиги, manifests и source snapshots не менять.
Итоги — `reports/comparisons/detection*.{csv,md}` и
[финальные таблицы](Итоги%20сравнительного%20анализа%20моделей.md).

Ограничения: разные штатные размеры и предобучение; COCO test — часть val2017;
внешний набор не использован; PyTorch VRAM не отражает весь CUDA-контекст и драйвер.
Будущее приложение остаётся отдельной задачей по [pipeline.md](pipeline.md).
