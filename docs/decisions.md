# Решения проекта

## 08.10.2026 — Первый реализованный этап: только детекция

По пользовательской задаче реализуется сравнение четырёх детекторов из плана. Веса размещаются в `detection/models/` вместо ранее предложенного общего `models/`: пользователь явно указал этот путь. Классификация, captions, API/БД/UI и общий pipeline остаются будущими этапами.

Проверенный CPU — Intel Core i5-12450H; прежнее i5-12400K было записано со слов пользователя и не подтверждалось. В WSL2 Ubuntu 26.04 доступно около 7.6 GiB RAM, несмотря на 16 ГБ физической памяти хоста. Контейнеру эксперимента назначен лимит 6 GiB. Драйвер Windows 610.78 / NVIDIA-SMI Linux 610.55, RTX 4050 Laptop 6141 MiB. Эти значения и фактические доступные RAM/VRAM сохраняются в environment manifest каждого запуска.

Окружение: PyTorch 2.7.1 + CUDA 12.8 / torchvision 0.22.1 в базовом образе с immutable digest; версии модельных библиотек проверены совместно, полный набор зависимостей закреплён в `detection/requirements.lock.txt`. Системный Python 3.14 не используется для ML-инференса. Новые пакеты в системный Python не устанавливались.

NVIDIA Container Toolkit отсутствует, sudo требует интерактивный пароль. Вместо изменения системного Docker добавлен отдельный WSL-профиль с `/dev/dxg`, `/usr/lib/wsl/lib` и `/usr/lib/wsl/drivers` read-only. CUDA проверена реальной tensor-операцией внутри контейнера. Для других Linux-хостов предусмотрен обычный `gpus: all`. GPU-профиль не меняет dtype и алгоритм модели.

Состав сравнения — архитектурные представители из плана; строгий рейтинг популярности не доказан. Seed 42, COCO val2017 500 dev / 4500 test фиксируются до измерений. AP floor 0.001/max 300, evaluator maxDets 100, P/R/F1 threshold 0.5 и IoU 0.5 зафиксированы заранее. Подбор порогов не выполняется. GPU FP32, batch 1, 20 прогревов, три повтора; TF32 и cuDNN autotuning отключены для воспроизводимости. CPU — отдельный эксперимент.

Полный test-benchmark и 1000-повторный парный bootstrap пользователь запускает подготовленными командами; собственная приёмка кода включает офлайн-smoke всех четырёх моделей и сокращённую dev-оценку. Она не заменяет итоговый анализ 4500 изображений и не даёт оснований выбирать победителя.

## Проверки реализации

Офлайн GPU-smoke всех четырёх моделей прошёл на COCO 397133 (640×427), включая сравнение staged preprocessing/forward/postprocessing со штатным predict и обратное преобразование bbox. В ходе первого dev20-прогона обнаружена ошибка оценщика для пустого GT-массива класса; неуспешные артефакты сохранены. Ошибка исправлена и покрыта регрессионным тестом. Отдельный тест проверяет стабильность хеша manifest после JSON-сериализации счётчиков и парный bootstrap с повторяющимися image_id. Финальный проверочный прогон и пути результатов фиксируются в `reports/verification/detection.md`.


## 08.10.2026 — Исправление RF-DETR после полного test-v1

Пользователь выполнил полный test-v1. Девять проходов YOLO26s, RT-DETRv2 R18 и Faster R-CNN завершились (4500 изображений × 3), RF-DETR во всех трёх повторах остановился после 253 изображений: на COCO 179285 низкий score floor выявил неиспользуемый ID 66. Голова pretrained RF-DETR имеет sparse COCO slots, включая фон и пропуски; адаптер ошибочно воспринимал их как фатальную ошибку. Исправление исключает только неиспользуемые позиции 0–90 и только для RF-DETR. ID не перенумеровываются; ID вне диапазона вызывают ошибку. Количество исключений сохраняется по изображениям в timings и суммарно в CSV. Настройки, веса и разбиение не меняются. Это исправление контракта словаря, а не подбор качества после просмотра test.

Штатный RF-DETR predict сохраняет unmapped IDs с пустым именем; нормализация benchmark исключает эти же slots. Реальный офлайн GPU-smoke на проблемном изображении 428×640 прошёл native-parity: 296 валидных детекций, 3 исключённые позиции. Артефакты: reports/detection/smoke-rf-gap-fix. В scripts/detection.sh проверка NVIDIA runtime теперь использует Bash, без внешнего rg.

test-v1 не изменяется. scripts/recover_detection.py создаёт новую версию test-v2 и переносит только девять завершённых неизменённых проходов. Проверяются config/dataset/model/image/source hashes и исходный snapshot; AST-проверка доказывает, что удаление RF-DETR-only исправления восстанавливает прежний адаптер, а обычный evaluator не изменён. Каждая перенесённая строка сохраняет исходные environment/source manifests и ссылку carried_forward; CSV содержит reused_from. Три исходных сбоя перечислены в recovery.json. RF-DETR запускается полностью заново, без переноса 253 частичных изображений. Сравнение задержек выполнено в разные моменты; это ограничение явно сохраняется.

Bootstrap ускорен без изменения определения AP: COCOeval.evaluate вычисляет независимые совпадения один раз по изображениям/категориям; для каждой парной выборки повторяются match records и заново выполняется официальный COCOeval.accumulate на уровне датасета. Учитываются кратности и порядок выбранных изображений, stable ties, crowd и ignore; per-image AP не усредняется. Регрессионный тест сравнивает с прямым пересчётом COCO на повторно индексированных изображениях, включая дубликаты и равные scores. Bootstrap checkpoints позволяют продолжить после остановки с проверкой hashes исходников, разметки и сырых predictions. Одновременно в памяти остаются predictions только одной модели.

Проверки исправления: 13 pytest-тестов прошли, Ruff check/format и Bash/Compose проверки прошли. Полные доверительные интервалы публикуются только после завершения 1000 повторов на реальных артефактах.


Полный test-v2 и bootstrap завершены: 12 complete-проходов по 4500 изображений и 1000 парных выборок для каждой модели. RF-DETR mAP 0.5283556, YOLO 0.4752690 (точные значения в CSV); RF-DETR имеет устойчиво положительные парные интервалы относительно остальных участников. Нижняя граница RT-DETR − YOLO составляет около 4.54e-7: округление до четырёх знаков скрывает её, а вывод остаётся пограничным при конечном числе bootstrap-выборок. Интервал YOLO − Faster R-CNN включает ноль. Генератор reports/comparisons/build_detection_analysis.py публикует полные парные числа и выводы из сохранённых артефактов; его исходник и SHA фиксируются отдельно от замороженного benchmark. Итоги и графики опубликованы локально в reports/comparisons; Git commits и внешняя публикация не выполнялись.

## 08.10.2026 — Классификация ImageNet: подготовка, без итоговых метрик

Подготовлен отдельный `classification/` и Compose ML-образ на той же закреплённой связке PyTorch 2.7.1/torchvision 0.22.1. Участники строго из уточнённого плана: ResNet-50 V2, EfficientNetV2-S V1, ConvNeXt-Tiny V1, ViT-B/16 V1; zero-shot отсутствует. Выбор — архитектурные представители, не доказанный глобальный топ-4. Сохранены точные URL и полные SHA-256 готовых весов, native transforms, 1000 labels/synsets и лицензия реализации. Веса размещены в `classification/models/` как отдельном каталоге этапа; source snapshot не включает веса и токены.

Проверены доступность WSL/Docker и память, создано и проверено контейнерное окружение. Исходная попытка сборки отклонена из-за несовпадения Pillow с constraints; до любых измерений исправлена на фактически проверенную 11.0.0. Полный constraints-файл генерируется через версии distributions, без нерепродуцируемых conda file:// путей. Веса загружены, все четыре реальные GPU-smoke без сети и native-parity прошли. Это проверка работы на одном COCO-изображении без ImageNet GT; она не создаёт показателей Top-1/Top-5.

Источник данных выбран с пользователем: Hugging Face ILSVRC/imagenet-1k, только validation 50 000 изображений (14 parquet-shards). Пользователь сообщил о принятии условий на сайте. Revision и размеры закреплены до evaluation; gated LFS SHA-256 сохраняются в авторизованном плане до загрузки. Скрипт не создаёт аккаунт и не принимает условия за пользователя. Локальный токен `.secrets/hf_token` доступен только tools и исключён из Git/образов; benchmark работает без токена и сети. Потоковый импорт сохраняет исходные JPEG bytes, проверяет label order и 50 изображений на каждый из 1000 классов.

ImageNet до этой записи не получен; итоговые CSV не содержат выдуманных результатов. Протокол заранее фиксирует 5000 evaluation (5/class, seed 42), затем отдельный полный validation50k с теми же настройками, FP32/batch1/20 warmup/3 repeats. Bootstrap парный стратифицированный по классу, percentile CI95 Top-1/Top-5, 1000 выборок; это соответствует сбалансированной выборке, отличается от COCO bootstrap по изображениям. Пересекающиеся 5000 и 50 000 не объявляются независимыми. Один shared inference lock, модельный child завершается до следующего; raw samples/timings и ошибки сохраняются. Git status снимается wrapper на хосте, чтобы частичные контейнерные mounts не выглядели как удалённые исходники.

Модуль пока охватывает только whole-image ImageNet. GT-crops, detector-crops, проверенный mapping ImageNet→COCO и оценка ошибочных изменений относительно detector-only остаются невыполненной частью сравнения. Завершённость всего раздела классификации и выбор победителя не заявляются.


## 08.10.2026 — Предварительная оценка и уточнение объёма пользователем

ImageNet validation получен через локально сохранённый личный HF read token после
принятия условий. Все 14 shard SHA-256 и оригинальные JPEG проверены. Для имени
с встроенным synset введена проверка перед канонизацией; exact aliases трёх
официальных различий написания не меняют порядка классов. Загрузка не затрагивает
train/test; секреты исключены из Git, логов и runtime benchmark.

Завершён evaluation5000 (4 × 3 × 5000), Top1: ResNet 80.70%, EfficientNetV2S 83.96%,
ConvNeXtTiny 82.60%, ViT 80.92%. Результаты и анализ в
reports/comparisons/classification-evaluation5000-v1/. Предсказания между повторами
идентичны. Отбор 5/class и все настройки закреплены до получения оценок.

Прикладные GT/detector-crops реализованы отдельно: консервативный mapping,
500 test-сцен, RF-DETR-Small repeat1 как фиксированный источник рамок,
class-agnostic matching IoU0.5. Условная точность, покрытие, пропуски и
исправленные/внесённые ошибки вычисляются раздельно; гипотетическая gated-замена
не меняет сохраняемую detector_category. Пороги score0.5/margin0.1 до оценки
зафиксированы как диагностические, не калиброваны как надёжный отказ; правило
рабочего конвейера потребует dev. Покрытие словаря — 55.81% non-crowd GT выбранных
сцен. COCO не подтверждает породы или другие тонкие ImageNet-подтипы.

Последнее указание пользователя: сегодня только тестовые прогоны, полные позже.
Поэтому full validation50k и полный crop benchmark не запускались; crop GPU-smoke
ограничен двумя вырезками в каждом режиме для всех четырёх моделей, без метрик
качества. Это заменяет предыдущие планы запуска полных экспериментов сегодня.

Пользователь отменил дальнейший расчёт доверительных интервалов. Уже полученный
bootstrap сохранён в исходных артефактах, основной report по умолчанию его не читает
и не включает CI в таблицы. Сравнение делается описательно по значениям данного
прогона. Старые измерительные конфиги и snapshots не переписываются задним числом.

Пользователь дополнительно разрешил push в существующий origin. WSL обнаружил
Windows Git Credential Manager, но авторизация пока не завершена: remote-запросы
ожидают вход, попытка push прервана timeout. Локальные результаты можно коммитить;
не объявлять их опубликованными до успешного push и проверки remote refs.

Позднейшее указание пользователя в том же чате разрешило full validation50k
только для первой модели ResNet-50. Добавлен --model как фильтр расписания,
не меняющий зафиксированных участников и experiment identity. Другие модели
остаются not_run до отдельного запуска; resume требует прежних исходников.
Три повтора, FP32/batch1 и параметры checkpoint сохраняются, CI не запускается.
