## Продукт

- Один компьютер с Docker; персональные абсолютные пути WSL не использовать. Текущая сборка Linux x86_64 containers; CPU и CUDA режимы явные, ограничения аппаратуры документировать честно.
- FastAPI + Elasticsearch + S3 (по умолчанию локальный MinIO) + RabbitMQ + Celery worker + статический nginx frontend. API модели не запускает; очередь содержит только image_id; concurrency/prefetch/batch 1.
- Elasticsearch хранит аннотацию всей сцены, классификацию, детекцию и ссылки на вырезки; бинарников изображений в индексе нет. Постоянно в S3 хранятся только вырезки. Исходные байты не сохранять; нормализованный вход держать только до обработки в общем временном каталоге API/worker и удалять после успешной публикации. Выгрузка JSON/вырезок — по выбору пользователя. По поручению пользователя от 07.11.2026 внешний S3 выбирается через APP_S3_ENDPOINT_URL; без внешнего адреса launcher поднимает локальный MinIO. При ошибке внешнего S3 не переключаться на локальный; данные автоматически не переносить.
- RF-DETR Small и Florence-2-base-ft. Детекция и описание сцены параллельны; затем один Florence последовательно описывает crops с padding10%. Сохранять raw_caption/object_caption, исходные bbox/COCO labels/байты без подмены. ViT не загружать.
- Результат готов после загрузки всех вырезок в S3 и одной условной записи полного документа в Elasticsearch. Общей транзакции ES/S3 нет: при сбое возможны вырезки без ссылки; не удалять файлы при неоднозначном подтверждении. Готовый UUID при повторной доставке не пересчитывать; exactly-once не обещать.
- Будущий поиск учитывать в Elasticsearch mapping, но интерфейс запросов и определение цвета пока не реализовывать. Не выдумывать структурированные атрибуты из caption.
- Сохранить текущую двухколоночную компоновку, выделение всех bbox, доступность, автоматическое ожидание и добровольную выгрузку. Технические пути в UI не показывать.
