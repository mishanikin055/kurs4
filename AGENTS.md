## Рабочие правила

- Общение и документация — на русском, код/идентификаторы — на английском.
- Основной репозиторий: origin https://github.com/mishanikin055/kurs4.git, разработка в dev. Проверять git status и не затирать чужую работу. Завершённые проверенные изменения коммитить содержательными подзадачами; push в существующий origin разрешён. В main переносить только завершённые проверенные изменения.
- Пользователь поручил руководителю делегировать задачи, проверять код и архитектуру. Субагенты: gpt-6.1-sol, reasoning medium; повышать reasoning только при неудовлетворительном результате. Astra запрещена.
- geo-models — отдельное приложение в общем https://gitlab.com/tatarov-k/img_analys.git, не встраивать его в этот проект и не затирать соседние приложения. Военный мониторинг исключён пользователем из задачи.
- Перед работой читать README.md, OPERATIONS.md и относящийся код. Не выдавать планы и старые отчёты за текущее состояние.
- Минимальная понятная архитектура, существующие API/service/repository; не добавлять платформы, лишние обёртки, Redis, Kubernetes и сервис на каждую модель.

## Продукт

- Один компьютер с Docker; персональные абсолютные пути WSL не использовать. Текущая сборка Linux x86_64 containers; CPU и CUDA режимы явные, ограничения аппаратуры документировать честно.
- FastAPI + PostgreSQL + RabbitMQ + Celery worker + статический nginx frontend. API модели не запускает; очередь содержит только image_id; concurrency/prefetch/batch 1.
- Медиаданные постоянно хранятся в PostgreSQL, бинарники отдельно от каталога. Локальные пользовательские копии/ZIP только по выбору пользователя. Временный scratch для моделей допустим, постоянный image volume не возвращать.
- RF-DETR Small и Florence-2-base-ft. Детекция и описание сцены параллельны; затем один Florence последовательно описывает crops с padding10%. Сохранять raw_caption/object_caption, исходные bbox/COCO labels/байты без подмены. ViT не загружать.
- Результат готов только после одной успешной транзакции артефактов/объектов/manifest. Готовый UUID при повторной доставке не пересчитывать. Отказ commit может потребовать повторного инференса; exactly-once не обещать.
- Будущий SQL-поиск учитывать в схеме/индексах, но интерфейс запросов и определение цвета пока не реализовывать. Не выдумывать структурированные атрибуты из caption.
- Сохранить текущую двухколоночную компоновку, выделение всех bbox, доступность, автоматическое ожидание и добровольную выгрузку. Технические пути в UI не показывать.
