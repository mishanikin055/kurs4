# Инструкции по курсовому проекту

## О проекте

«Программное средство детекции и классификации объектов и аннотирования изображений с использованием искусственной нейронной сети».
Пользователь загружает изображение, получает рамки объектов, классификацию каждой вырезки и общее текстовое описание от отдельной модели. Результаты сохраняются; по аннотации выполняется поиск в открытых источниках.
Научная часть — три сравнительных анализа по четыре готовые модели: детекция, классификация и аннотирование. Обучение, fine-tuning и LoRA не входят в проект.

При расхождении приоритет имеют актуальные указания пользователя и зафиксированные в тематических документах уточнения.

## Общие правила

- Общение и проектная документация — на русском; код, идентификаторы и имена файлов кода — на английском. Основной язык — Python.
- Основная рабочая копия — `/home/mikhail/kurs4`, WSL2 Ubuntu 26.04; команды — Linux/Bash. Единственный репозиторий — https://github.com/mishanikin055/kurs4.git, существующий `origin`. Ветки — `codex/<task>`; до изменений проверить Git status и не затирать чужую работу.
- Приложение и сравнения запускаются в Linux Docker Compose. Стек приложения: FastAPI, PostgreSQL JSONB, SQLAlchemy/миграции, один Python worker, Streamlit.
- Порядок: **детектор → классификатор всех вырезанных объектов → отдельный аннотатор → согласование**. Batch size 1. Одновременно строго одна модель в RAM/GPU; модельный дочерний процесс должен завершиться до следующего. Приложение и benchmark используют общий `storage/locks/inference.lock`.
- Оборудование: RTX 4050 Laptop, 6 ГБ VRAM; Intel Core i5-12450H; 16 ГБ RAM хоста, около 7,6 GiB доступно WSL. До тяжёлой работы проверить фактическую память и smoke.
- Только готовые веса. Не добавлять zero-shot CLIP/SigLIP2 без новой задачи. Сохранять исходное изображение, результаты всех этапов и overlay; исходный `raw_caption` неизменен.
- По указанию пользователя от 09.10.2026 новые доверительные интервалы не рассчитывать ни в одном сравнении: детекторы, классификаторы и аннотаторы. Ранее сохранённые расчёты не удалять; старые конфиги и примеры bootstrap не отменяют это правило.
- Актуальное число прогонов по указанию пользователя от 09.10.2026: полный ImageNet у классификаторов закончить после двух кругов; для аннотаторов — один прогон каждой модели. Уже завершённые три повтора детекции, evaluation5000 и crop-сравнений, а также третий полный ResNet-50 сохранить. В основном ImageNet-сравнении использовать одинаковые первые два повтора всех четырёх моделей; прежние конфиги не переписывать задним числом.
- Токен Hugging Face хранить только в игнорируемом `.secrets/hf_token`, не выводить в чат/логи. Веса, datasets, кэши, окружения, секреты и пользовательские изображения не добавлять в Git.
- Пользователь разрешил коммитить завершённые проверенные изменения и push в существующий origin. Обычную обратимую реализацию выполнять без повторных запросов разрешения. Материалы руководителю без отдельной задачи не отправлять.
- Исходные материалы не удалять и не реорганизовывать. Источник требований — `Материалы для курсовой/Аникин_задание на курсовую.docx`, пункты 3.1–3.6, и уточнения пользователя. Старый план-график не использовать. Исходные DOCX при правке документации не менять. Сроки сдачи: проект работы — 15.12.2026, законченная работа — 22.12.2026.

## Состояние и завершение работы

На 09.10.2026 сравнения детекторов и классификаторов завершены; полный ImageNet — два круга, crops — ранее завершённые три. Ограничения описаны в classification.md. Аннотаторы, приложение, UI, общий конвейер и поиск ещё не реализованы. За подробным статусом обращайся к выбранному тематическому документу.

Сначала маленький работающий вертикальный сценарий, затем расширения. Не создавать заглушки с фиктивным успешным результатом. Использовать типизацию, небольшие адаптеры, явные исключения и конфиги.

До команд проверять существующие инструменты и тесты. При наличии соответствующей конфигурации выполнять релевантные `python -m pytest`, `python -m ruff check .`, `python -m ruff format --check .` в выбранном окружении; после правки Markdown полный GPU-benchmark не нужен. Реальные model smoke и быстрые mock-тесты отмечать отдельно. PostgreSQL integration и smoke всех 12 моделей обязательны перед финальной приёмкой.

Обновлять затронутые тематические инструкции, README, конфиги и manifests; крупные отклонения фиксировать в `docs/decisions.md`. В конце указать изменения, проверки и оставшиеся ограничения. Не писать «всё работает» после одних статических проверок.
