## 3. Целевая структура

```text
scripts/
  detection/
    yolo26s.py
    rtdetr_v2_r18.py
    rf_detr_small.py
    faster_rcnn.py
    common.py
  classification/
    resnet50.py
    efficientnet_v2_s.py
    convnext_tiny.py
    vit_b_16.py
    common.py
  annotation/
    blip_base.py
    florence2_base_ft.py
    qwen3_vl_2b.py
    smolvlm2_500m.py
    common.py
  prepare.py
  export_tables.py
```

**Скрипт модели** содержит явную загрузку её локальных готовых весов, штатную
подготовку изображения и получение предсказания. По файлу должно быть понятно,
какая библиотека и модель используются. Не делай четыре пустые обёртки,
вызывающие старый CLI, диспетчер или общий универсальный адаптер моделей.

**Общий файл направления** содержит простые функции чтения набора, обработки
изображений, замеров, метрик и сохранения таблиц. Он не должен превращаться
в универсальную экспериментальную платформу. Не добавляй новые слои runner,
service, registry или plugin ради этой переделки.

**`prepare.py`** — единая явная подготовка данных и весов с выбором направления:
загрузка, проверка закреплённых источников и SHA-256, подготовка manifests.
Используй существующие проверенные реализации, упростив их размещение.
Сравнение не должно скачивать файлы автоматически.

**`export_tables.py`** объединяет полный и презентационный экспорт сохранённых
таблиц в Word. Нужен явный выбор варианта и нового выходного файла/каталога.
Не перезаписывай прежние DOCX и их manifests автоматически. Зависимость
`python-docx` оставь в отдельном окружении экспорта, не добавляй её в ML ради удобства.

Данные остаются в `data/`, веса — в существующих `detection/models/`,
`classification/models/`, `annotation/models/`. Не переименовывай большие
каталоги ради названия `datasets`. Сохрани необходимые справочники классов,
точные версии зависимостей и проверенный сторонний код CHAIR с лицензиями.
Тесты и данные для метрик допустимы отдельно от пяти файлов направления.

После переноса нужной логики удали из активной реализации прежние CLI,
runner, shell-обёртки, дублирующие команды и код новых crop-запусков.
Не оставляй параллельно старую платформу и новые скрипты.
Исторический код доступен через Git и существующие source snapshots.
Исторические файлы внутри `reports/` сохраняются, даже если среди них есть код.

## 4. Docker и интерфейс запуска

- Один основной Compose-файл с тремя ML-сервисами и один дополнительный
  файл доступа к GPU в текущей WSL.
- Сохрани три отдельных проверенных ML-окружения. У детекции и аннотирования
  различаются версии Transformers; объединять всё в один Python-образ нельзя
  без отдельного обоснования и проверки.
- Запуск — прямой командой Docker Compose с нужным Python-файлом.
  Python-скрипты не вызывают Docker, Docker socket им не передаётся.
- Сохрани закреплённые Docker-зависимости и подходящие существующие Dockerfile,
  изменив точки входа и mounts под новую структуру.
- Runtime работает офлайн, данные и веса подключены read-only.
  Подготовка с доступом к сети выполняется явно отдельно от сравнения.
- В этой WSL ранее использовался `/dev/dxg` и read-only библиотеки драйвера:
  не предполагай наличие NVIDIA Container Toolkit; проверь фактический доступ.

Для всех двенадцати скриптов одинаковые параметры:

- `--run NAME` — обязательное имя **нового** сравнения.
- `--limit N` — необязательная положительная граница короткой проверки.
- `--report-only` — восстановление таблиц из сохранённых новых результатов
  без загрузки нейросетевых весов и инференса.

Четыре модели направления запускаются последовательно с одинаковым `--run`.
Каждый запуск обновляет общую CSV/Markdown-таблицу направления. В ней ровно
четыре участника, включая незапущенных и ошибочных с явным статусом.
Результаты разных наборов, параметров и `--limit` не должны незаметно смешиваться
под одним именем сравнения.

Новые результаты хранятся отдельно от исторических экспериментов.
Повторная запись существующего результата модели запрещена; после прерывания
используется новое имя сравнения. Сложное resume посреди набора не реализовывать.
Короткий запуск явно помечается и не выдаётся за полное сравнение.

## 5. Данные, модели и измерения

Используй прежние точные checkpoint, источники, label mapping и подготовленные
наборы. Не меняй участников и параметры ради упрощения кода.

| Направление | Четыре модели | Набор по умолчанию |
|---|---|---|
| Детекция | YOLO26s; RT-DETRv2 R18; RF-DETR Small; Faster R-CNN ResNet50 FPN V2 COCO_V1 | `data/coco/test.json`, 4500 изображений |
| Классификация | ResNet-50 IMAGENET1K_V2; EfficientNetV2-S IMAGENET1K_V1; ConvNeXt-Tiny IMAGENET1K_V1; ViT-B/16 IMAGENET1K_V1 | `data/imagenet/validation.json`, 50 000 изображений |
| Аннотирование | BLIP base; Florence-2 base-ft; Qwen3-VL 2B Instruct; SmolVLM2 500M Video Instruct | `annotation/configs/test500.json`, 500 изображений |

Сохрани штатные transforms, пороги, прогрев и параметры генерации.
Детекция и классификация — прежний FP32; аннотаторы — проверенный FP16,
greedy decoding и 96 новых токенов. Новое число проходов — один для всех.
Старые конфиги завершённых экспериментов с другим числом повторов не переписывай
задним числом: новый протокол фиксируется отдельно.

Обязательные метрики:

- Детекция: COCO AP/AR, precision/recall, показатели по категориям.
  Используй проверенный официальный COCO evaluator. Сохрани score floor 0.001,
  исходные max detections 300, evaluator maxDets `[1, 10, 100]`,
  score/IoU 0.5 для precision/recall. Не фильтруй AP пользовательским порогом.
- Классификация: Top-1, Top-5, Macro-F1 и показатели по всем 1000 классам.
  Проверь порядок меток и synsets всех checkpoint.
- Аннотирование: CIDEr, BLEU-4, ROUGE-L, CHAIRs/CHAIRi.
  Сохраняй `raw_caption` неизменным. На вход подаётся исходное изображение
  без ответов детектора и классификатора.
- Для всех: p50/p95, скорость, время загрузки, RAM и PyTorch
  allocated/reserved VRAM с единицами измерения и честным пояснением ограничений.

Сохраняй предсказания и измерения по изображениям в JSONL, параметры,
происхождение и статус запуска в JSON, итоговые метрики в CSV/Markdown.
Ошибки и OOM фиксируются явно. Не выдавай неполные данные за итог полного набора.
Не создавай множество дублирующих файлов с одними и теми же сведениями.

Особенно важно сохранить исправление **sparse COCO slots RF-DETR**:
неиспользуемые slots его головы исключаются; произвольные неизвестные ID
остаются ошибкой. Координаты рамок должны соответствовать исходному изображению,
xyxy и COCO xywh не смешиваются. Проверяются resize, letterbox и EXIF.

**Новые доверительные интервалы, bootstrap, обучение, fine-tuning, LoRA,
zero-shot CLIP/SigLIP2, человеческая оценка и новые полные прогоны ради
рефакторинга не нужны.** Старые интервалы и все полученные результаты сохраняются.

Batch size 1. Во всей системе загружена строго одна модель в RAM/GPU.
Общий lock — `storage/locks/inference.lock`; он должен защищать реальный
модельный процесс до завершения. Следующая модель запускается после завершения
предыдущего процесса. `empty_cache()` само по себе этого не обеспечивает.
Учитывай сбои и остановку контейнера, не допускай фоновых живых модельных потомков.
