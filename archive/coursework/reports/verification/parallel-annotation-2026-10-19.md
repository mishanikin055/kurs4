# Параллельное аннотирование — 19.10.2026

## Изменение

По запросу пользователя `process_image(image_id)` выполняет две параллельные ветки:
RF-DETR Small → ViT-B/16 и Florence-2 base-ft на целом нормализованном изображении.
Два потока стандартного ThreadPoolExecutor координируют существующие отдельные
модельные процессы через IPC. CUDA в координаторе Celery не инициализируется.
Одновременно обрабатывается одно изображение; concurrency/prefetch/batch 1.

Полный комплект из original, normalized.png, detection.png, results.json публикуется
только после обеих успешных веток; затем сохраняется одна строка processed_images.
Дубликаты и повтор commit готового комплекта не запускают модели повторно.
Формат API, схема БД, checkpoint и научные сравнения сохранены.

Обычная ошибка дожидается завершения второй ветки, чтобы не оставить непрочитанный
IPC-ответ для следующего изображения. При остановке координатора или потере
резидентного процесса/таймауте/OOM общий сигнал отмены прерывает активные запросы.
После этого worker перезапускается и незавершённое сообщение возвращается в очередь.
Для одноразовых модельных процессов отмена завершает process group до выхода.

## Проверки

Целевые локальные CPU/mock-тесты:

```bash
.venv-backend/bin/python -m pytest -q backend/tests/test_pipeline.py backend/tests/test_processing.py backend/tests/test_runtime.py
```

**59 passed**. Проверены перекрытие аннотатора с детекцией/классификацией через
синхронизацию событий, ожидание любой из двух веток перед файлами/БД, ошибки без
готовой записи, отмена обоих запросов, освобождение одноразового процесса и
прерывание резидентного IPC. Проверка перекрытия не опирается на сравнение времени.

Полный локальный запуск `.venv-backend/bin/python -m pytest -q backend/tests`:
**78 passed, 16 skipped** за 7.89 с. Пропуски требуют настоящих БД/брокера;
они отдельно включены в инфраструктурный запуск ниже.

Настоящая инфраструктура с синтетическими моделями:

```bash
docker compose -p kurs4-parallel-test -f compose.app.yaml up -d --wait db rabbitmq
docker run --rm --name kurs4-parallel-test-runner --network kurs4-parallel-test_default --env-file .secrets/app.env -e APP_TEST_INTEGRATION=1 -v "$PWD/backend:/app/backend:ro" -v "$PWD/pyproject.toml:/app/pyproject.toml:ro" kurs4-backend-test:v2 sh -c 'alembic -c backend/alembic.ini upgrade head && python -m pytest -q backend/tests'
docker compose -p kurs4-parallel-test -f compose.app.yaml down --volumes
```

**93 passed, 1 skipped** за 101.59 с. Использован ранее собранный тестовый образ;
текущий код backend и конфигурация pytest подключены read-only. Только отдельные
PostgreSQL, RabbitMQ, очередь, volumes и Celery consumer проекта kurs4-parallel-test.
Рабочие БД, очередь, image volume и GPU worker проекта kurs4-app не изменялись.
После проверки тестовые контейнеры, сеть и созданные в этой задаче volumes удалены.

Режим синтетических моделей `parallel` требует старта аннотатора до ответа детектора
и старта классификатора до ответа аннотатора; последовательный код его не проходит.
Он проверен через отдельный Celery worker с постоянными и одноразовыми процессами.
Проверены также остановка worker во время долгого аннотирования в обоих режимах,
завершение его процессов, возврат сообщения в очередь и успешная повторная доставка.
Отдельно проверена потеря резидентного аннотатора с рестартом consumer и redelivery.

Пропущен прежний сценарий внешнего отключения PostgreSQL: ему нужен отдельный
controller APP_TEST_OUTAGE_CONTROL. Сценарий ошибки commit с сохранённым комплектом
проверяется CPU/mock-тестом. Предупреждения — прежние Starlette/httpx и Alembic.

Ruff check и format --check по репозиторию, git diff --check и Compose config
CPU/GPU прошли. Конфигурация реального GPU проверялась только статически.

## Ограничения

Настоящие модели, GPU smoke и научные сравнения не запускались. Одновременная
нагрузка на RTX 4050, её пиковая RAM/VRAM и реальное ускорение не измерены.
Прежний smoke от 13.10.2026 относится к последовательному инференсу.
Параллельные запросы не гарантируют ускорение на одной GPU.

Рабочий контейнер не пересобран и не пересоздан: он продолжает использовать
прежнюю версию до обновления. Для применения завершить текущую очередь,
пересобрать и пересоздать worker по README. Его запуск загружает и прогревает
настоящие модели и не выполнялся в этой задаче.
